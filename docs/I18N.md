# Internacionalización (i18n)

InversorIA usa un diccionario central en [`i18n.py`](../i18n.py) y la función `_('KEY')` en toda la UI Streamlit.

## Idiomas

- `es` (por defecto)
- `en`

El idioma se guarda en `st.session_state['language']` (selector en sidebar de [`app.py`](../app.py)).

## Convenciones de claves

| Prefijo | Uso | Ejemplo |
|---------|-----|---------|
| `NAV_`, `DASH_` | Navegación y dashboard | `NAV_SETTINGS` |
| `CFG_KEY_{SETTING}` | Etiqueta de parámetro en Ajustes | `CFG_KEY_RISK_PER_TRADE` |
| `CFG_HELP_{SETTING}` | Ayuda del campo | `CFG_HELP_RISK_PER_TRADE` |
| `CFG_CHOICE_{KEY}_{value}` | Opciones de select | `CFG_CHOICE_DECISION_MODE_hybrid` |
| `ERR_CFG_*` | Errores del importador | `ERR_CFG_MIN` |
| `LOG_TAG_*` | Tags en visor de logs | `LOG_TAG_SKIP` |
| `HIST_*` | Historial / analítica | `HIST_FILTER_EVENTS` |

## Parámetros de configuración (168+ claves)

Las etiquetas se generan con:

```bash
python scripts/sync_cfg_i18n.py
```

- Salida: [`i18n_config_labels.py`](../i18n_config_labels.py) (auto-generado).
- Overrides humanos: [`i18n/config_overrides.yaml`](../i18n/config_overrides.yaml).

Al importar `i18n`, `CFG_LABELS` se fusiona en `TRANSLATIONS`.

## Reglas para desarrolladores

1. **No** poner texto visible al usuario como literal en `st.button("...")` — usar `_('KEY')`.
2. Añadir siempre **es** y **en** en el mismo PR.
3. Tras añadir claves a `CONFIG_SCHEMA`, ejecutar `sync_cfg_i18n.py`.
4. Validación local:

```bash
python scripts/audit_i18n.py --fail-on-warn
python -m unittest tests.test_i18n_parity -v
```

## Errores de configuración

El importador lanza `ConfigValidationError` con códigos `ERR_CFG_*`. La UI debe mostrar:

```python
from i18n import format_config_error
from config_importer import ConfigValidationError, format_validation_error
```

## Logs en terminal

El cuerpo del log sigue siendo el texto del daemon. La UI traduce **tags** (`[SKIP]`, `[BUY]`, …) vía `ui_services/log_display.py`.
